# AI 创作者平台导航

**在线访问：https://jlfjiao.github.io/ai-creator-platform-nav/**

按生成能力分模块收录，优先国内可用。只收录各品类中使用人数较多、较为常用的平台，热门度不足的不再收录，因此各模块数量不等（24–30 条）。排序默认国内优先 · 使用人数，可切换为名称排序。使用人数仅少数平台有公开数据（QuestMobile / Sensor Tower / 公司财报），无公开数据的条目不做数字臆测；消费档只与同类型平台比较，为同类内相对位置，不跨模块换算。

单文件静态站：无构建、无依赖、无外部请求，直接打开 `index.html` 即可使用。

## 数据口径

### 消费档

只在同一模块内比较，不跨模块换算。视频类的「中」与对话类的「中」不是同一金额。

| 档位 | 在本类中的位置 | 说明 |
| --- | --- | --- |
| 很高 | 该类最高 | 企业年约、按席位售卖或最高档订阅，个人难以长期自付 |
| 高 | 高于该类中位 | 专业订阅，订阅后可稳定商用 |
| 中 | 该类主流付费档 | 有免费额度，付费门槛不高 |
| 低 | 低于该类中位 | 免费额度 + 几十元级会员 |
| 很低 | 该类最低 / 免费 | 免费，或仅承担本地算力成本 |

人民币参考（编辑归纳，非报价）：视频生成 ¥100–200/月；图片生成、代码生成、对话与推理、音频与音乐、办公与文档、设计与原型 ¥70–150/月；智能体与低代码 ¥150–300/月。

每个模块至少有一个「高」或「很高」、一个「低」或「很低」的条目，但不强制出现「很高」，避免造成该类普遍昂贵的误读。

### 评分

采用以下四维评分。每个平台只按它所在的模块评估：**模型能力里的任务分禁止跨类相减**——代码生成模块的模型只比代码生成，视频生成模块只比视频生成，图片、音频、办公、设计、智能体同理。同一平台跨模块时，任务分和总分都按模块分别给出，避免把不同用途混为一个名次。

| 维度 | 权重 | 评分要点 |
| --- | ---: | --- |
| **模型能力** | **60%** | 由两个子项合成：**语言理解 20% + 本模块任务能力 80%** |
| 工作流与可靠性 | 25.6% | 易上手、速度、成功率、稳定性、导出/协作/集成；按可重复操作观察 |
| 性价比 | 8% | 在相同预算或相同任务量下比较有效产出，不把免费额度等同于高性价比 |
| 证据与成熟度 | 6.4% | 官方文档、更新记录、服务状态与条款是否清楚、可复核；不按声量或用户总数直接加分 |

每项 0–10 分，按 `总分 = 模型能力×0.60 + 工作流可靠性×0.256 + 性价比×0.08 + 证据成熟度×0.064` 计算，最终四舍五入到 0.1 分；其中 `模型能力 = 语言理解×0.20 + 本模块任务能力×0.80`。先记录原始分、日期、任务和证据，再算总分。

模型能力的两个子项：

- **语言理解（占模型能力 20%）**：跨模块通用的能力口径，看指令语义理解、推理与深度研究、长上下文、多语言与中文场景、以及检索问答/文档理解。评分依据是**记录自带的能力标签**（不用评价数据）；**无信号时按中性基准 7.0，不臆测**（221 条中 157 条落在基准，属正常：多数生成类平台没有可引用的理解类公开标签）。
- **本模块任务能力（占 80%）**：只在本模块内部横向定位。代码类只比代码生成质量，视频类只比视频生成，音频类只比音频生成，图片、办公、设计、智能体各按各的。

去掉「专项适配与功能」一维：它原先占 11.4%，评分依据是「命中了多少个专精标签」，本质是功能覆盖面而不是效果好坏——宣传页写了某个功能，不等于这个功能好用；而且覆盖面与本模块任务能力重复计分。删掉后不再单列这一项，相关判断并入本模块任务能力，在同一个真实任务里一并观察。

去掉「用户综合评价」一维：**采集到的第三方评价不再是评分依据。** 理由有三。①覆盖率不够——现存的 `ev` 只覆盖 60/221 条，剩下四分之三没有数据。②来源不可核验且不均——Reddit 返回 403、CSDN 返回 521，掘金/头条/公众号的点赞数由前端脚本渲染、静态页面读不到，能拿到的样本集中在少数被热议的产品上。③它测的不是同一件事——曝光度受发布时间、话题热度、作者粉丝量影响，用它打分等于给「恰好被讨论」加分、给「没人写测评」扣分，与模型本身的能力无关。保留一个只有部分数据、且数据与能力弱相关的维度，会产生系统性偏差而不是精度。

因此卡片上的第三方评价改为纯参考展示（`第三方评价 x.x/10，不计入本站评分` + 来源域名），不进公式；释放出的 8% 交给剩余三维，按其当时的权重（工作流 16 / 性价比 12 / 证据 4，合计 32）等比放大到 40，倍数 40 ÷ 32 = 1.25，得到工作流 20% / 性价比 15% / 证据 5%——正好回到这套权重最初的相对比例。

**性价比从 15% 下调到 8%**：释放的 7% 按剩余三维的当前比例（工作流 20 : 证据 5 = 4:1）等比放大，得工作流 25.6% / 证据 6.4%。理由是性价比在本站的数据条件下得分跨度过大——消费档映射后最低 2.5（很高）与最高 9.2（很低）相差 6.7 分，按 15% 权重会贡献约 1.0 分的差距，超过多数模型能力带来的差异。而这里的消费档只是**同类内的相对位置**（见「消费档」），免费工具自动拿 9.2、企业年约自动拿 2.5，其中相当一部分反映的是商业模式而不是用户拿到的价值——例如开源/本地部署的工具还需要自付硬件与运维成本。降到 8%（贡献约 0.54 分差距）后，名次主要由能不能把活干好决定；价格信息仍在卡片上单独显示（消费档标签 + 人民币参考），读者自己做判断比塞进总分更清楚。

为什么权重集中到模型能力：本榜单回答的是「用这个模型能不能做出好东西」。同模块内，成品质量差距远大于界面流程或价格差距；把权重压在这里，名次主要由产出质量决定，避免文档成熟度这类外围项把实际更弱的模型顶上去。

#### 各项评分锚点

所有维度统一采用以下锚点：

| 分数 | 通用含义 |
| ---: | --- |
| 0 | 不支持、不可用，或有证据确认无法完成该项 |
| 1–2 | 明显不满足基本需求，失败或重大限制常见 |
| 3–4 | 能完成少数简单任务，限制明显，需大量绕行 |
| 5–6 | 满足一般需求，存在可见短板或额外成本 |
| 7–8 | 多数目标任务表现好，限制较少，有可复核依据 |
| 9 | 同类中表现突出，重复使用仍稳定，重要优势有证据支持 |
| 10 | 在明确测试范围内近乎无短板；须有公开任务集或充分重复测试支撑，少用满分 |

维度落地方法：

1. **语言理解**：所有模块通用。固定一组测试指令，覆盖三层：①字面指令遵循（照做 vs 曲解）；②隐含意图与否定句（“不要出现 X”“只改第 2 段”）；③长上下文保持（万字文档问答、多轮一致性）。再测一次歧义指令是否主动追问，而不是臆测执行。440 字以内的短指令与超过 1 万字的长输入分别记录成功率，中文与英文各测一遍。原理简单：少了这一层，后面所有任务能力都无从谈起，所以按 20% 计入。
2. **本模块任务能力**：每个模块预先选 3–5 个常见任务，固定输入、提示词和成功标准；每任务至少重复 3 次。评价成品可用度、指令遵循、错误/瑕疵和人工返工量。代码看测试通过率与改动正确性，图片/视频/音频由盲评者按预设量表评分，办公与智能体看事实正确率及任务完成率。**只与同模块产品比较**：拿自己在 code 类里排出的名次去和 video 类对比没有意义。
3. **工作流与可靠性**：用相同网络和设备完成一条典型流程，记录成功次数、耗时、崩溃/排队、导出质量、协作或集成步骤及人工介入。建议按成功率、稳定性、流程摩擦各占约三分之一；样本太少时标为低置信度。
4. **性价比**：选定地区、套餐、币种、税费口径和月任务量，计算“月成本 ÷ 合格交付数量”，同时记录免费额度、限速和超额成本。以同模块候选的中位成本为参照：成本显著低且限制少可给 8–10；接近中位给 5–7；显著更贵且无相应质量优势给 0–4。开源/本地工具也计入硬件、部署和维护成本。
5. **证据与成熟度**：评的是信息可信和产品可持续使用的把握，不是产品能力或人气。检查官方文档/价格/条款是否清楚且更新，更新记录和服务状态是否可查。来源缺失应标“证据不足”，不要把缺数据当 0 分，也不要凭用户数直接加分。

#### 关于第三方评价为什么仍展示但不计分

卡片上保留 `ev`（来源域名、评价分、摘要）供自行参考，但明确标注“不计入本站评分”。展示与计分分开处理，是为了两件事都不出错：既不丢掉已经采到的、可被读者复核的信息，也不把一份只覆盖 27% 条目、来源分布不均的数据当成普遍依据。

如果以后要用它计分，需要同时满足：①每个模块的覆盖率达到可比较水平，而不是集中在对话类；②每个产品有足够样本（原定标准为至少 5 条视频、每条至少 30 条有效评论、覆盖 2 个以上平台）；③来源可核验——当前 Reddit 403、CSDN 521、多个中文平台的互动数由前端渲染导致静态页面读不到，这条路径暂时走不通。三条齐全之前，它只能当参考。

#### 实际评分流程

1. 确定模块、地区、日期、典型用户和预算；只在同类内排分。
2. 为语言理解和本模块任务能力分别选定任务与量表，所有候选用同一条件；先测试再看品牌，尽可能盲评。
3. 至少两人独立评分；分差超过 2 分时回看证据并写明裁决理由。每项保留来源链接、测试日期、样本数和置信度（高/中/低）。
4. 对价格与产品版本注明地区、套餐及核查日期；三个月或重大版本变化后复核。
5. 先发布语言理解、本模块任务能力两项分数及其余维度分数和证据，再展示加权总分。数据不足时显示“待评/低置信度”，不要复制其他维度分数填空；关键维度缺失时不计算总分，避免虚假精确。

当前页面旧字段 `cap/sp/pz/rp` 不足以承载这套新量表；审计发现 221 条记录中有 208 条的 `rp` 与 `cap` 完全相同。因此这批数据不能直接转换成可信的新四维评分，必须按上述流程重新补主体任务的实测证据并重评。旧分数应视为临时编辑估值，不是独立用户口碑或权威排名。

##### 重算结果（v5 · 性价比下调至 8%）

四轮权重调整：**第一轮**模型能力 30% → 60%，其余五维按 40 ÷ 70 压缩；**第二轮**删除「专项适配与功能」，释放的 11.4% 按剩余四维原比例分配；**第三轮**删除「用户综合评价」，评价数据退出评分，释放的 8% 由剩余三维按 40 ÷ 32 放大；**第四轮**性价比 15% → 8%，释放的 7% 按当时工作流 : 证据 = 20 : 5 的比例分配。

### 采集门槛与执行结果

两条硬门槛：**① 发布时间在近两个月内（2026-08-28 起）；② 来源具备可核验的高热度依据。**

「点赞数」一项的实测情况（直接抓取页面 HTML 校验）：

| 来源 | 结果 |
| --- | --- |
| Hacker News（Algolia 接口，points 直读） | 可核验；两个月内 points > 2000 的仅 DeepSeek 一帖（2352 分、892 条评论，2026-10-20），已写入 `ev` |
| Reddit（各产品社区 top 帖） | 403 Blocked，无法读取 |
| CSDN | 521 Web 服务器拒绝，无法读取 |
| 掘金 / 今日头条 / 微信公众号 | 点赞数由前端动态渲染，静态 HTML 中不存在该字段，无法读取 |

因此中文横评类来源的点赞数在当前技术路径下**无法自动核验**。本轮采用等效门槛：**来源必须给出可引用的量化评价（评分表、实测评分或个人体验打分）**，而非仅有定性描述。凡不满足「窗口内 + 有量化依据」的条目一律清除 `ev`，用户评价维度回落至 6.0，卡片上不显示评价行。

当前覆盖：56 个平台、60 条记录（去重后 221 个条目中约四分之一）。已清除：全部窗口外的旧采集数据，以及无量化依据的条目。点赞数可人工补核后写回 `ev.src`。

规范中的「双人独立评分」尚未执行；已有来源域名记录在 `ev.src`，可据此回溯原文。
